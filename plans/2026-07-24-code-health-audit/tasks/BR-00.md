# BR-00 — Settle the per-run phase contract

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `sol_xhigh`
- Reviewer profile: `sol_xhigh`
- Depends on: `ARCH-01`, `JR-00`, `JR-02`
- Work type: claim-to-terminal ownership contract

## Objective

Define the typed phases and ownership transfers currently fused inside
`beadRunOne`: Resolve → Prepare → Launch/Execute → Finalize → Terminal. Define
one immutable `RunPlan` and explicit phase results. No production extraction.

## Evidence to verify first

Trace every effect in `beadRunOne`, existing `runexec` machines,
`runloop.RunEnv/RunPorts/SharedHandles`, runlaunch, RunBridge, all three modes,
queue/Bead/Run terminal writes, and the normative Run state specifications.

## Exclusive lease

Kerf/spec artifacts and `tasks/evidence/BR-00.yaml`. No production Go files.

## Required work

1. Assign branch/model/harness/workflow/placement resolution to `RunPlan`.
2. Assign worker/tunnel/worktree/session acquisition and cleanup.
3. Define a common mode-executor result without erasing mode-specific facts.
4. Define finalization versus durable terminal-effect ownership and ordering.
5. Enumerate crash/cancel cuts and legal retry/adoption decisions.
6. Map existing JR and PI tasks to the phase owner they must modify.

## Acceptance

- Every current `beadRunOne` responsibility maps to exactly one phase.
- Each phase has complete inputs, typed output, and no hidden global lookup.
- Ownership transfer and cleanup are explicit for every error/cancel boundary.
- The contract enables independent phase tasks without concurrent giant-file
  edits.

## Verification

Kerf/spec review, exhaustive responsibility matrix, crash-cut review, and
independent Run/queue/process cross-group approval.

## Escalate when

Stop if the design changes normative terminal policy, creates a generic god
port, or cannot assign a resource to one Wait/cleanup owner.
