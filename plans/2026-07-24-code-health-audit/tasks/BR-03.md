# BR-03 — Extract mode execution behind one result contract

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `sol_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `BR-02C`, `PS-02`, `RL-03`, `DOT-03`
- Work type: serial beadRunOne mode-boundary decomposition

## Objective

Replace the inline single/review/DOT branch inside `beadRunOne` with three mode
executors consuming a complete plan/resource scope and returning one typed,
lossless execution result. Do not perform durable queue/Bead terminal effects.

## Exclusive lease

The mode-switch region of `workloop.go`, narrow mode interfaces/adapters, and
focused cross-mode tests. Sole `dispatch_spine` writer; no shared baseline file.

## Required work

1. Define the common result fields and explicit mode-specific payloads.
2. Adapt the already-decomposed review and DOT coordinators.
3. Extract the remaining single-mode phase shell.
4. Remove mode-specific process lifecycle duplication.
5. Delete the old inline branch and meet the exact approved metrics.

## Acceptance

- Each mode has one production executor and one result mapping.
- Cancellation, no-change, failure, success, and ambiguous outcomes remain
  distinguishable.
- Mode execution cannot close/reopen a Bead or release queue ownership.
- Cross-mode lifecycle conformance tests pass.

## Verification

Mode contract tests, local real-process scenarios, race/repeat, architecture
gate, delta lint, UBS, and `make check-fast`.

## Escalate when

Stop if a mode cannot preserve necessary facts without changing normative
terminal semantics.

## Return

Use the directory return contract. **COMMIT EXPLICITLY.**
