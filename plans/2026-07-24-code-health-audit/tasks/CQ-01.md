# CQ-01 — Enforce the queue admission transaction

## Dispatch metadata

- Group / priority: core queue / P0
- Execution profile: `terra_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `CQ-00`, `CQ-02I`
- Work type: bounded contract-conformance implementation

## Objective

Make supported CLI/socket submission and append obey the existing admission
contract: validate completely, persist exactly once before install/wake/events,
and leave no runnable in-memory item on rejection or durable-write failure.

## Evidence to verify first

Use `tasks/evidence/CQ-00.yaml`, `specs/queue-model.md` QM-050/QM-063, and:

- `internal/queue/rpc.go` `HandleQueueSubmit`, `HandlerAdapter.HandleQueueSubmit`,
  `appendUnderLock`, and the unlocked fallback;
- `internal/queue/cli` submit/append;
- `internal/daemon/bootsocket.go` production adapter construction.

## Exclusive lease

- `internal/queue/rpc.go` and focused RPC tests
- exact submit/append CLI composition tests, if needed
- no `internal/daemon/workloop.go`, persistence implementation, or queue state
  kernel edits

## Required work

1. Add failing-first boundary tests for accepted, validation-rejected, persist-
   failed, and concurrent same-name requests.
2. Exercise the production `HandlerAdapter` with its real mutation-lock shape.
3. Remove or fail closed on any production-reachable unlocked mutation fallback;
   retain a test-only compatibility seam only if the reviewer can prove it is
   absent from production wiring.
4. Verify event/wake ordering from observable effects, not internal call counts.

## Acceptance

- Rejection and persistence failure leave disk and caller-visible memory
  unchanged and emit no success event.
- Successful submit/append persists before install, wake, or success events.
- Concurrent same-name admission has one winner and no lost accepted request.
- Production wiring cannot select the unlocked fallback.

## Verification

Focused queue RPC tests, race test for concurrent submit/append, scoped vet/lint,
UBS, independent production-call-site review, and post-commit `make check-fast`.

## Escalate when

Stop if satisfying the tests requires a new persisted generation/CAS contract,
changing queue file format, or editing the dispatch stamp; those belong to
`CQ-02` or `CQ-03`.

## Return

Use the directory return contract. **COMMIT EXPLICITLY.**
