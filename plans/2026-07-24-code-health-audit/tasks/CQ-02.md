## Decisions that must be settled

1. **Canonical topology and compatibility.** Reconcile singleton
   `.harmonik/queue.json` wording with named queues under
   `.harmonik/queues/<name>.json`. Define which layouts are readable, writable,
   migrated, archived, and rejected. Preserve supported file formats unless an
   explicit operator decision is required.
2. **One mutation owner.** Name the production transaction owner and the exact
   lock/generation rule that serializes RPC, workloop, lifecycle, operator,
   eager-refill, budget, review-failure, startup, inline, and placeholder
   callers. State whether direct persistence remains legal anywhere.
3. **Immutable transaction input.** Define clone → validate → mutate → persist
   → install ordering. A stored/live queue pointer must never expose an
   uncommitted mutation. Define generation/CAS behavior for stale snapshots.
4. **Persistence result taxonomy.** For create, temp write, file sync, close,
   rename, parent-directory open, sync, and close, define results that
   distinguish:
   - definitely not committed;
   - committed and directory-durable;
   - indeterminate after namespace mutation.
   Specify retry, reload/reconcile, degraded-state, mutation refusal, and
   operator visibility for each result. A plain error that callers can
   misinterpret as “nothing changed” is not sufficient after rename/unlink.
5. **Memory and event visibility.** For every result category define whether
   the QueueStore installs, retains, reloads, or clears state; when Wake is
   legal; and which domain events may be emitted. Preserve QM-063's durable
   before emit rule.
6. **Admission and group activation.** Settle whether submit plus first-group
   activation is one transaction or two ordered transactions, and the exact
   placement of `queue_submitted` and `queue_group_started`.
7. **Completion landmark.** Define the exact order among item/group terminal
   mutation, completed-state persistence, final `queue_group_completed`,
   QueueStore clearing, unlink, and directory sync. Cover both normal workloop
   completion and startup reconciliation.
8. **Shutdown.** Define cancel persistence, archive rename, QueueStore
   ownership, restart behavior, and same-name resubmission for every
   pre/post-rename fault.
9. **Migration.** Define one-valid-copy behavior when legacy only, destination
   only, both, neither, invalid legacy, invalid destination, and faults occur
   around copy/rename/delete/directory sync. CQ-MIG-01 implements the selected
   rules but does not choose them.
10. **Implementation DAG.** Produce exact, non-overlapping slices for CQ-02I
    and every caller migration identified by CQ-00. Each slice names task ID,
    prerequisites, lease family, exact production symbols/files, failing-first
    proof, accepted intermediate state, and rollback boundary. Propose missing
    task records in evidence; do not edit `TASK-INDEX.yaml`.

## Required crash matrix

The design must give an unambiguous result and recovery action for:

- temp create, write, file sync, and close failures;
- canonical rename failure;
- target rename success followed by directory open/sync/close failure;
- completed-state persist before final event;
- canonical unlink failure;
- unlink success followed by directory failure;
- shutdown cancel persist and archive rename at every boundary;
- migration destination creation, legacy deletion, and both-copy startup;
- process death after each successful namespace mutation but before the next
  effect;
- concurrent stale-generation mutation attempts.

Every row states durable state before, attempted effect, possible disk states
after, caller-visible memory, returned result category, permitted next effects,
restart classification, and implementation task owner.

## Non-negotiable boundaries

- Beads owns terminal Bead transitions. CQ-02 owns only queue state and its
  transaction/recovery contract.
- Run/event payload schemas remain owned by execution-model/event-model.
- The process lifecycle owns daemon degraded/ready state vocabulary.
- Queue mutations never use LLM cognition.
- No multi-process queue writer may be introduced without an operator
  decision; the current per-project daemon singularity is preserved.
- No caller may treat an indeterminate persistence result as definitely
  uncommitted or continue dispatch from memory without reconciliation.
- No new generic repository-wide durability abstraction is introduced. The
  separate durable-state work remains independent.

## Acceptance

- Every CQ-00 crash cut maps to one result category, memory action, restart
  action, and implementation owner.
- One queue transaction owner covers every production writer class.
- Named/singleton topology and migration have one non-contradictory contract.
- Persist/install/Wake/event ordering is explicit for success, definite
  failure, and indeterminate completion.
- Completion and shutdown cannot clear live ownership while leaving an
  unclassified canonical blocker.
- Implementation slices are independently dispatchable and do not overlap
  semantic-writer leases.
- Both independent reviewers approve.
