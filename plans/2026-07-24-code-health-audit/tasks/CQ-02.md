## Decisions that must be settled

1. **Canonical topology and compatibility.** Reconcile singleton
   `.harmonik/queue.json` wording with named queues under
   `.harmonik/queues/<name>.json`. Define which layouts are readable, writable,
   migrated, archived, and rejected. Preserve supported file formats unless an
   explicit operator decision is required.
2. **One mutation owner.** Name the production transaction owner and the exact
   lock/generation rule that serializes RPC, workloop, lifecycle, operator,
   eager-refill, budget, review-failure, startup, inline, and placeholder
   callers. State whether direct persistence remains legal anywhere.
   Generations are volatile, process-local stale-snapshot guards only; they
   are never persisted and never used as restart identity.
3. **Immutable transaction input.** Define clone → validate → mutate → persist
   → install ordering. A stored/live queue pointer must never expose an
   uncommitted mutation. Define generation/CAS behavior for stale snapshots
   and classify request/candidate validation plus stale-generation rejection
   as `rejected` before namespace I/O.
4. **Persistence result taxonomy.** For create, temp write, file sync, close,
   rename, parent-directory open, sync, and close, define results that
   distinguish:
   - definitely not committed;
   - committed and directory-durable;
   - indeterminate after namespace mutation.
   Specify retry, reload/reconcile, degraded-state, mutation refusal, and
   operator visibility for each result. A plain error that callers can
   misinterpret as “nothing changed” is not sufficient after rename/unlink.
   Marshal, candidate-temp write/sync/close, logical-effect construction, and
   every filesystem failure before durable intent creation are
   `not_committed`; validation and stale generation are not included in that
   category. Once the intent is durable, later cuts are classified by the
   exact intent/canonical/temp state rather than collapsed into
   `not_committed`.
5. **Memory and event visibility.** For every result category define whether
   the QueueStore installs, retains, reloads, or clears state; when Wake is
   legal; and which domain events may be emitted. Preserve QM-063's durable
   before emit rule. Every ordinary canonical replacement—create, submit,
   append, reservation, Run-ID patch, activation/advance, pause/resume,
   eager refill, budget/review charge, maintenance/reconciliation, startup,
   inline/bootstrap, crew-placeholder creation, and cancelled-state replacement
   before archive—must use
   `.harmonik/queues/<normalized-name>.replace-intent` as an exact recovery
   outbox. The protocol order is mandatory:
   snapshot/validate/clone/mutate/marshal; write, fsync, and close the exact
   candidate temp while constructing the ordered logical effects; durably
   create the replace intent; only then mutate the canonical namespace.
   Validation and stale input are `rejected`. Marshal, candidate-temp, and
   logical-effect construction failures before durable intent creation are
   `not_committed`.

   The intent records transaction ID, operation, queue/canonical identity,
   exact prior/candidate byte digests, selected already-durable temp basename,
   Wake requirement, and ordered logical effects. Each logical effect records
   `effect_key = transaction_id + ordinal`, ordinal, event type, canonical
   payload, and canonical payload digest. It records no event ID. On append,
   the event subsystem mints a normal event ID through its ordinary path.
   Recovery confirms an exact prefix of logical effects by effect key, type,
   canonical payload, and digest; it appends only the missing suffix in order.
   A hole, reorder, duplicate-key mismatch, type mismatch, or payload/digest
   collision quarantines. Wake is repeatable. RPC responses are never
   persisted or replayed. The Class O `queue_cancelled_operator` audit is
   excluded from this logical-effect outbox.

   Queue-model owns construction of the effect key and ordinal, logical order,
   intent persistence, and the recovery decision. Event-model owns the minimal
   required-effect substrate: persist the logical effect key in the event
   envelope (the current design uses exact `trace_context.trace_id`; a final
   equivalent requires explicit normative definition), perform a bounded
   from-zero exact lookup, compare event type plus canonical post-redaction
   payload and digest, append a missing effect idempotently with a normal
   append-time event ID, report exact-match/missing/collision/hole/reorder,
   `FlushThrough` the appended event before success, and apply the existing
   torn-tail classification/recovery rules. The queue owner may remove the
   intent only after the entire logical prefix is confirmed and flushed.
6. **Admission and group activation.** Settle whether submit plus first-group
   activation is one transaction or two ordered transactions, and the exact
   placement of `queue_submitted` and `queue_group_started`.
7. **Completion landmark.** Define the exact order among item/group terminal
   mutation, completed-state persistence, final `queue_group_completed`,
   QueueStore clearing, unlink, and directory sync. Cover both normal workloop
   completion and startup reconciliation. QM-051 owns the final state
   transition but does not emit its final event. QM-053 is the sole
   confirm/emit owner for exactly one final `queue_group_completed` logical
   effect. Normal execution and restart recovery confirm the same effect key;
   the event subsystem mints its normal ID only when that logical effect is
   actually appended.
8. **Shutdown and operator cancellation.** Define cancel persistence, archive
   rename, QueueStore ownership, restart behavior, and same-name resubmission
   for every pre/post-rename fault. Define the stable replace-intent/outbox
   design used for the synchronous cancelled-state replacement: stable
   transaction identity, queue name/ID and exact-byte digest binding, atomic
   replace semantics, required-effect confirmation, removal, and retry
   ordering. Do not use volatile generations as restart identity.
9. **Migration.** Define one-valid-copy behavior when legacy only, destination
   only, both, neither, invalid legacy, invalid destination, and faults occur
   around copy/rename/delete/directory sync. CQ-MIG-01 implements the selected
   rules but does not choose them.
10. **Implementation DAG.** Produce exact, non-overlapping slices for CQ-02I
    and every caller migration identified by CQ-00. Each slice names task ID,
    prerequisites, lease family, exact production symbols/files, failing-first
    proof, accepted intermediate state, and rollback boundary. Propose missing
    task records in evidence; do not edit `TASK-INDEX.yaml`.
11. **Process-lifecycle amendment.** Make the smallest complete PL delta that:
    inventories every queue-cancel wire path; makes daemon-unreachable
    cancellation unconditionally fail closed with exit 17 and no canonical,
    temp, archive, intent, legacy, or event write; and defines intent
    capability negotiation, version compatibility, downgrade refusal, replay
    ownership, and operator-visible recovery only for target-daemon
    startup/upgrade resolving owner-written intents. The capability gate must
    require the event-model key persistence, bounded exact lookup, idempotent
    append, collision/hole/reorder result, FlushThrough, and torn-tail
    behavior before intent recovery begins. Capability support never creates a
    daemon-down local-write fallback. Do not generalize this into a
    repository-wide intent protocol.
12. **Event-model amendment.** Make the smallest complete event-model delta for
    two queue-required surfaces:
    - the required-effect substrate described above, including its exact
      persisted key field, bounded from-zero query contract, canonical
      post-redaction payload/digest comparison, prefix-consistent idempotent
      append with ordinary append-time IDs, typed
      exact/missing/collision/hole/reorder results, `FlushThrough`, and
      torn-tail behavior; and
    - typed Class O `queue_cancelled_operator`: its
      parseable-versus-corrupt payload XOR, queue emitter, and exact position
      after durable archive/legacy cleanup, archive-intent removal, and
      QueueStore/refusal release but before the successful RPC response.
      This audit is best-effort, non-replayed, has no required-effect key, and
      is excluded from the replace-intent outbox. Append failure is diagnostic
      only: it cannot roll back or change a successful cancellation, recreate
      an intent, reacquire ownership, or suppress the successful RPC response.
      Graceful shutdown never emits it.
13. **Wire/status/changelog accuracy.** Define QueueStatus selector precedence:
    nonempty `name` selects by name and ignores `queue_id`; empty `name` plus

## Required crash matrix

The design must give an unambiguous result and recovery action for:

- temp create, write, file sync, and close failures;
- canonical rename failure;
- target rename success followed by directory open/sync/close failure;
- completed-state persist before final event;
- canonical unlink failure;
- unlink success followed by directory failure;
- shutdown cancel persist and archive rename at every boundary;
- universal replace-intent/outbox create, write, file sync, close, namespace
  replacement, directory open/sync/close, pre-intent candidate-temp creation,
  logical-effect construction, candidate/canonical replacement, repeated Wake,
  each ordered logical-effect confirmation/append, and intent removal at every
  boundary for every ordinary replacement class;
- process death with exact prior bytes visible, exact candidate bytes visible,
  neither visible, invalid/third bytes, a prefix of logical effects appended,
  a hole/reorder/collision in confirmations, or Wake already delivered;
- required-effect lookup from offset zero reaches its bound, observes an exact
  match, observes a same-key type/payload/digest collision, encounters a torn
  tail before/after a candidate match, or reports hole/reorder across ordinals;
- required-effect append succeeds but `FlushThrough` fails or process death
  occurs before/after the flush boundary; intent cleanup remains forbidden
  until the exact prefix is durably confirmed;
- process death after applying operator cancellation but before archive
  cleanup/release, before the best-effort `queue_cancelled_operator` attempt,
  after its append failure, or before the RPC response; recovery never replays
  that audit or response;
- valid, corrupt, unsupported, and coexisting replace/archive intent
  capability cases at target-daemon startup, plus capable upgrade and
  incapable downgrade/rollback refusal;
- daemon-unreachable cancel with byte-identical before/after canonical, temp,
  archive, intent, legacy, and event state and exit 17;
- migration destination creation, legacy deletion, and both-copy startup;
- process death after each successful namespace mutation but before the next
  effect;
- concurrent stale-generation mutation attempts.

Every row states durable state before, attempted effect, possible disk states
after, caller-visible memory, returned result category, permitted next effects,
restart classification, and implementation task owner.

## Non-negotiable boundaries

- Beads owns terminal Bead transitions. CQ-02 owns only queue state and its
  transaction/recovery contract.
- Run payload schemas remain owned by execution-model. Event payload schemas
  and event-log durability/query mechanics remain owned by event-model. CQ-02
  may amend only the minimal required-effect key/lookup/append/FlushThrough/
  torn-tail substrate and the separate `queue_cancelled_operator` audit through
  that spec's amendment protocol.
- Queue-model owns logical-effect key construction, ordinal/order, intent
  storage, and recovery policy. Event-model owns key persistence in the event,
  bounded exact lookup, canonical post-redaction comparison, append-time ID
  allocation, idempotent append, typed collision/hole/reorder results,
  FlushThrough, and torn-tail handling. Neither spec may silently take the
  other's side of this boundary.
- The process lifecycle owns daemon degraded/ready state vocabulary and
  queue-cancel intent capability/downgrade behavior; CQ-02 may amend only the
  minimal queue-cancel surface required by this contract.
- Queue mutations never use LLM cognition.
- No multi-process queue writer may be introduced without an operator
  decision; the current per-project daemon singularity is preserved.
- No caller may treat an indeterminate persistence result as definitely
  uncommitted or continue dispatch from memory without reconciliation.
- No new generic repository-wide durability abstraction is introduced. The
  separate durable-state work remains independent.

## Acceptance

- Every CQ-00 crash cut maps to one result category, memory action, restart
  action, and implementation owner.
- One queue transaction owner covers every production writer class.
- Named/singleton topology and migration have one non-contradictory contract.
- Persist/install/Wake/event ordering is explicit for success, definite
  failure, and indeterminate completion.
- Every ordinary canonical replacement uses one durable replace intent that
  records exact prior/candidate digests, selected temp and transaction
  identity, Wake requirement, and exact ordered logical effects keyed by
  transaction plus ordinal. Recovery confirms only a prefix and appends the
  missing suffix; any collision/hole/reorder quarantines. Event IDs are minted
  normally only on append, and volatile generations are never restart
  evidence.
- Event-model persists the logical effect key, performs bounded from-zero exact
  type plus canonical post-redaction payload/digest lookup, returns typed
  exact/missing/collision/hole/reorder results, appends a missing suffix
  idempotently with normal append-time IDs, and completes `FlushThrough` before
  queue recovery may clean the intent. Torn tails cannot create false
  confirmation.
- Process-lifecycle refuses startup/upgrade intent recovery unless the target
  daemon advertises that complete required-effect capability.
- Validation and stale-generation refusal are `rejected` before namespace I/O;
  marshal, candidate-temp, and logical-effect construction failures before
  durable intent creation are `not_committed`. The canonical namespace is
  untouched until the exact temp and intent are durable.
- Completion and shutdown cannot clear live ownership while leaving an
  unclassified canonical blocker.
- QM-053 is the sole final-event owner; normal execution and restart recovery
  confirm or append exactly one matching final `queue_group_completed` logical
  effect.
- Daemon-down queue cancellation unconditionally writes nothing and returns
  exit 17. Intent capability gates apply only to target-daemon
  startup/upgrade/downgrade/rollback.
- The replace-intent/outbox crash matrix classifies every durable cut and makes
  exact effect confirmation and removal safe after restart.
- `queue_cancelled_operator` is typed Class O, best-effort, non-replayed, and
  outside the required-effect key/outbox substrate. It is attempted after durable
  cleanup/release and before the RPC response; append failure is
  diagnostic-only and cannot change cancellation success.
- QueueStatus selector precedence, retained wire fields/methods, source/target
  version drift, and `§3.2 QM-002c` are accurate in design, draft, and
  changelog.
- The process-lifecycle and event-model changes are minimal: no unrelated
  lifecycle state, event taxonomy, payload, or durability rule changes.
- Implementation slices are independently dispatchable and do not overlap
  semantic-writer leases.
- Both independent reviewers approve all three full-file drafts.

## Stop conditions

Stop without packaging or committing if:

- CQ-00 input identity or dependency state differs;
- root topology, semantic claim base, execution baseline, or existing Kerf
  identity/status differs;
- any active problem-space, component, research, design, changelog, task, or
  review artifact retains the stale one-spec scope;
- any historical `research-review.md`, `change-design-review.md`, or
  `spec-draft-review.md` blob differs from its recorded superseded input;
- the kerf path or any of the three full-file output drafts exists
  incompatibly;
- a required write falls outside the lease;
- the worker would need to write a normative spec or the coordinator would
  need to copy one before both reviews approve;
- resolving the contract requires changing any fourth normative spec;
- file-format compatibility needs an operator choice not already locked;
- a proposed owner violates daemon singularity or Beads/Run ownership;
- a crash cut remains “best effort,” “implementation-defined,” or lacks a
  recovery action;
- an implementation slice overlaps another slice's semantic writer;
- either reviewer cannot be independent.

Report the exact conflict and smallest operator/coordinator decision needed.
Do not implement production code through uncertainty.
