# CQ-04 — Make queue recovery a pure, idempotent decision

## Dispatch metadata

- Group / priority: core queue / P0
- Execution profile: `terra_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `CQ-RECEIPT`, `JR-01`
- Work type: pure recovery kernel plus narrow adapter

## Objective

Make the PL-005 queue startup phase consume QueueStore intent/receipt facts and
reach one fixed point without JSONL completion inference or final-event
synthesis.

## Evidence to verify first

Review startup queue reconciliation, orphan/in-flight reconciliation, queue
resume helpers, and existing state/recovery tests. Reuse an existing pure
decision machine if one already covers the needed states.

## Exclusive lease

- `internal/lifecycle/startup_pl005_qm002.go` `LoadQueueAtStartup`,
  `loadOneQueueAtStartup`, `reconcileQueueTerminalState`,
  `reconcileDispatchedItems`, and `reconcileThreeWay`
- exact QueueStore transaction/receipt adapters and focused tests
- no persistence primitive, reservation, terminalization, or process cleanup
  changes

## Required work

1. Define immutable inputs for queue item, durable Run record, Bead status, and
   trustworthy process/registry evidence.
2. Return typed decisions with reasons: no-op, retry pending, adopt, mark failed,
   or escalate ambiguity.
3. Add exhaustive table/property tests for terminal absorption, idempotence, and
   at-most-one runnable owner.
4. Keep I/O and event emission in a one-shot adapter.
5. Resolve every supported intent/receipt/canonical combination; corrupt or
   unsupported state fails closed. Never emit/replay final group observation.
6. Commit QM-002b A/D mutations together before A/D/C/B observation attempts.

## Acceptance

- Same evidence always yields the same reasoned decision.
- Applying the adapter twice performs no second launch or contradictory write.
- Ambiguous evidence fails closed and is observable.
- The kernel has no filesystem, process, ledger, clock, or event dependency.
- Receipt-governed cleanup and claim-loss correction are idempotent across
  restart; failed correction installs no partial queue.

Accepted intermediate: restart is queue-fact-only; live terminal call sites
remain `JR-03`. Rollback only the startup queue-recovery phase.

## Verification

Pure table/property tests, focused adapter fault tests, race test if shared
startup state is touched, vet/lint/UBS, independent recovery review, and
`make check-fast`.

## Escalate when

Stop if a needed fact is not durable or the task requires changing the process
ownership contract. File/split the missing evidence task.
