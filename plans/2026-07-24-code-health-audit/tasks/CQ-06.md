# CQ-06 — Keep queue logic behind narrow composition ports

## Dispatch metadata

- Group / priority: core queue / P1
- Execution profile: `terra_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `CQ-02I`, `ARCH-01`
- Work type: bounded ports/adapters cleanup

## Objective

Expose exactly the queue transaction, snapshot, recovery-decision, and terminal
effect ports consumed by the owners named in `ARCH-01`. Daemon composition must
not reach queue persistence or mutable internals directly. Do not introduce a
generic queue facade or defer consumer migration.

## Exclusive lease

- exact queue-domain ports and composition files identified by `CQ-00`
- their conformance tests
- no workloop dispatch/claim/terminal spine, persistence semantics, or global
  registries

## Required work

1. Inventory the minimal methods actually consumed by the queue domain.
2. Reuse existing interfaces where they already match.
3. Remove production-reachable optional/unlocked fallback wiring.
4. Add composition tests proving the real adapter is installed once.

## Acceptance

- Domain decisions can be tested without filesystem/event/Beads fakes that
  expose unrelated methods.
- Production composition has no nil/optional capability ambiguity.
- No interface is broader than its consumer.
- Package dependency direction remains compliant.

## Verification

Focused conformance/composition tests, depguard if affected, race/fault tests for
adapter changes, vet/lint/UBS, review, and `make check-fast`.

## Escalate when

Stop if a new cross-subsystem interface or shared service container is required.
