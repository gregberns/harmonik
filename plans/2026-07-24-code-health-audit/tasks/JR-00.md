# JR-00 — Characterize claim-to-terminal Run ownership

## Dispatch metadata

- Group / priority: job/run orchestration / P0
- Execution profile: `terra_high`
- Reviewer profile: `sol_xhigh`
- Depends on: none
- Work type: read-only deterministic evidence inventory

## Objective

Produce `tasks/evidence/JR-00.yaml`: a trace of queue dispatch stamp → Bead claim
→ Run ID/record/registry creation → launch → terminal decision → Bead and queue
release → restart recovery. Do not change behavior.

## Evidence to verify first

- `internal/daemon/workloop.go` `runWorkLoop`, `beadRunOne`, dispatch stamp,
  claim semaphore, group advance, and terminal helpers.
- `internal/daemon/runports.go`, `internal/runloop/ports.go`,
  `internal/runloop/runbridge.go`, and `internal/runexec`.
- `internal/daemon/runregistry.go`, on-disk run records, startup reconcile, and
  in-flight reconcile.
- Beads claim/reopen/close adapters and the queue item's `RunID`/status writes.

## Exclusive lease

- Read any source/test/spec.
- Write only `tasks/evidence/JR-00.yaml`.
- Do not edit production code, tests, the index, or CQ evidence.

## Required work

1. Build a transition table keyed by durable queue state, Bead state, run
   record state, registry state, and observable events.
2. Name the owner and ordering for each mutation; mark split or implicit
   ownership.
3. Enumerate crash windows capable of zero runs, duplicate runs, leaked claims,
   or terminal/release disagreement.
4. Map current unit/scenario/recovery tests to each transition.
5. Identify which facts are local-only and which require the primary daemon;
   do not treat deferred runtime proof as a missing unit assertion.

## Acceptance

- One queue item can be followed by immutable identifiers through every
  production call site.
- All claim, run-record, register/unregister, reopen/close, item terminal, and
  release writes are listed.
- The evidence distinguishes Run machine decisions from adapter side effects.
- Gaps are concrete enough to produce `JR-01` and `JR-02` without further broad
  repository exploration.

## Verification

- Run only narrow tests needed to validate disputed transitions.
- Validate the YAML parses.
- A frontier reviewer independently checks the real composition root and at
  least one restart path.

## Escalate when

Stop at evidence if source and specs disagree. Do not create a new transaction
or recovery policy.

## Return

Return the evidence path and reviewer findings; commit the accepted evidence
artifact explicitly.
