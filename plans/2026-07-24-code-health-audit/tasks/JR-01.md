# JR-01 — Make claim-to-Run creation unambiguous

## Dispatch metadata

- Group / priority: job/run / P0
- Execution profile: `sol_xhigh`
- Reviewer profile: `sol_xhigh`
- Depends on: `JR-00`, `CQ-03`
- Work type: serial dispatch-spine implementation

## Objective

After a durable queue reservation exists, make Bead claim, durable Run record,
and registry registration produce exactly one traceable Run or one recoverable
failure.

## Exclusive lease

- claim/Run creation region of `internal/daemon/workloop.go`
- on-disk Run record and registry adapters required by that region
- focused duplicate/crash tests
- no queue reservation (`CQ-03`) or terminalization (`JR-03`) edits

## Acceptance

Retry/crash cannot yield zero unclassified Runs or multiple Runs for one
reservation; claim failure is durably returned to the queue or fail-closed;
registry and durable record carry the same Run ID before launch.

## Verification

Fault/race tests around claim and record creation, controlled restart, lint/UBS,
review, check-fast.

## Escalate when

Stop if the approved queue reservation lacks a fact needed to correlate Run
creation; amend that contract rather than inventing an event heuristic.

## Return

Use the directory return contract. **COMMIT EXPLICITLY.**
