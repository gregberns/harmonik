# PS-02 — Bind local process/session adapters to the phase owner

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `sol_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `PS-01`
- Work type: bounded local lifecycle adapter

## Objective

Adapt the existing local substrate/tmux launch, readiness, input, signal,
Wait/reap, hook, watcher, and cleanup capabilities to the frozen `PS-01`
lifecycle protocol. Remote execution remains fail-closed/deferred.

## Evidence to verify first

Inspect `perRunSubstrate`, `tmuxSubstrate`, handler session lifecycle, runlaunch
helpers, existing process-tree tests, and every current Wait/kill owner.

## Exclusive lease

One local phase adapter, exact substrate/tmux/handler adapter methods, and
focused tests. No workloop/reviewloop/DOT integration and no remote protocol.

## Required work

1. Bind existing local effects to the frozen phase transitions.
2. Ensure exactly one Wait and bounded TERM/KILL/reap.
3. Close hooks/watchers/subscriptions in reverse acquisition order.
4. Prove terminal-before-bind and cancellation races.
5. Keep tmux substrate an adapter rather than a policy owner.

## Acceptance

- Real local child/process-group cleanup is bounded and leak-free.
- Repeated close/signal/terminal input converges.
- Remote capability absence fails closed.
- Mode integrations can consume the adapter without changing `PS-01`.

## Verification

Real local process tree, state conformance, fault/race/leak/repeat tests,
delta lint, UBS, and `make check-fast`.

## Escalate when

Stop if safe local cleanup requires workflow policy or remote protocol changes.
