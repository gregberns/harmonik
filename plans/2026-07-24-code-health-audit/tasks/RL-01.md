The only disposition values are:

- `landed_active_production`: the implementation is an ancestor of the
  analysis base and has a non-test production caller there;
- `landed_test_only`: only tests/fixtures are ancestors of the analysis base;
- `landed_unused_kernel`: implementation is on the analysis base but has no
  direct or compatibility-mediated production reachability;
- `staged_test_only`: absent from the analysis base, present on a pinned staged
  ref, and limited to tests or fixtures without a production implementation;
- `staged_active_boundary`: absent from the analysis base, present on a pinned
  staged ref, and production behavior there reaches it directly or through a
  compatibility API;
- `staged_unused_kernel`: absent from the analysis base, present on a staged
  ref, and without production reachability there;
- `equivalent_current_tree`: a separately landed analysis-base implementation
  is proven symbol-, caller-, behavior-, and test-equivalent;
- `planned_unlanded`: only the canonical kerf task definition exists;
- `blocked_dirty_worktree`: implementation exists only as the pinned uncommitted
  L8 snapshot and its required probe is blocked;
- `superseded`: a later reviewed artifact explicitly replaces the task and
  equivalence or deletion evidence proves that replacement.

Do not use `equivalent_current_tree` without symbol, caller, test, and diff
evidence proving equivalence. Do not use `superseded` merely because a later
plan exists. If one kerf task has mixed results, select the disposition that
