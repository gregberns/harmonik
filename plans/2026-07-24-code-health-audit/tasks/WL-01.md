# WL-01 — Freeze outer work-loop behavior

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `terra_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `ARCH-00`

## Objective

Create deterministic behavior traces for the current `runWorkLoop` control
loop before decomposition: maintenance, pause/capacity gates, queue and br-ready
selection, reservation/claim, spawn, completion, cancellation, shutdown, and
restart. No production refactor.

## Exclusive lease

Focused daemon/runloop tests and fixtures plus `tasks/evidence/WL-01.yaml`.
Production files are forbidden.

## Required work

1. Record ordered decisions/effects for one iteration of each dispatch source.
2. Replace timing-sleep assertions with barriers, fake clock, or controlled
   effect logs.
3. Cover idle wakeup, periodic maintenance, pause, disk/capacity refusal,
   persistence failure, claim failure, spawn, completion, and shutdown.
4. Prove the harness exercises production construction or state precisely where
   it uses a controlled adapter.

## Acceptance

- Each responsibility later extracted from `runWorkLoop` has a stable oracle.
- The harness detects effect reordering and duplicate ownership.
- Tests do not depend on the primary daemon or wall-clock races.

## Verification

Focused tests, race and repeat runs, mutation of one effect ordering, lint, UBS,
and `make check-fast`.

## Escalate when

Stop if observability requires a production-only testing hook or changes
queue/claim semantics; split that seam for architecture review.
