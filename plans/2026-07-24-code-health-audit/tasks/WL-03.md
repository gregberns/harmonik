# WL-03 — Extract dispatch-source selection

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `sol_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `ARCH-01`, `ARCH-GATE`, `WL-01`, `WL-02A`, `WL-02B`, `WL-MUT-01`
- Work type: serial workloop decomposition

## Objective

Extract queue and br-ready candidate acquisition into one typed
`DispatchCandidate` decision boundary. Selection must not mutate a live queue,
claim a Bead, mint a Run, or start a process.

## Evidence to verify first

Use `WL-01`, especially the `loaded_queue_suppresses_br_ready` and
`idle_submit_wake` gap returns, the extracted `WL-02B` gate decision, existing
queue-selection code, and exact `ARCH-01` metric targets.

## Exclusive lease

Selection/pre-screen regions of `workloop.go`, existing pure
`internal/orchestrator` selection code, the `ARCH-01` target owner, and focused
tests. Sole `dispatch_spine` writer.

## Required work

1. Define explicit queued/direct candidate variants and immutable identity.
2. Reuse current pure queue selection; group advancement is terminal ownership
   and is explicitly excluded.
3. Move eligibility, capacity, blocked-project, and source arbitration behind
   the boundary without durable effects.
4. Remove the duplicate inline selection path.
5. Add a deterministic entered-idle or entered-wait rendezvous and an
   observable wake/re-evaluation boundary. The proof must not be satisfiable by
   closing the wake channel before the loop is known to be blocked.
6. Close `loaded_queue_suppresses_br_ready` with a production-composition trace
   proving that a loaded, non-contributing queue never calls `Ready`.
7. Close `idle_submit_wake` with a production-composition trace proving that
   the loop is blocked before submit wake and re-selects the queue without a
   timer expiry afterward.
8. Add mutations for bypassing loaded-queue suppression and consuming an early
   wake; prove that both oracles reject them.
9. Lower `runWorkLoop` complexity/span and forbid queue pointer escape.

## Acceptance

- Candidate selection is pure for a captured fleet/ledger snapshot.
- Queued candidates carry enough identity for later revalidation.
- No activation, deferral mutation, reservation, claim, persist, Run
  registration, terminal/group advancement, or process effect occurs here.
- A loaded, non-contributing queue deterministically suppresses `Ready`.
- Submit wake is observed only after the loop is known to be waiting and causes
  deterministic queue re-selection without wall-clock timing.
- The exact pre-approved architecture target is met.

## Verification

Table/property tests, named `loaded_queue_suppresses_br_ready` and
`idle_submit_wake` production-composition traces, suppression/early-wake
mutation tests, race/repeat composition tests, architecture gate, delta lint,
UBS, and `make check-fast`.

## Escalate when

Stop if one source cannot be represented without changing its normative claim
or reservation authority.
