# WL-03 — Extract dispatch-source selection

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `sol_high`
- Reviewer profile: `sol_xhigh`
- Depends on: `ARCH-01`, `ARCH-GATE`, `WL-01`, `WL-02A`, `WL-02B`, `WL-MUT-01`
- Work type: serial workloop decomposition

## Objective

Extract queue and br-ready candidate acquisition into one typed
`DispatchCandidate` decision boundary. Selection must not mutate a live queue,
claim a Bead, mint a Run, or start a process.

## Exclusive lease

Selection/pre-screen regions of `workloop.go`, existing pure
`internal/orchestrator` selection code, the `ARCH-01` target owner, and focused
tests. Sole `dispatch_spine` writer.

## Required work

1. Define explicit queued/direct candidate variants and immutable identity.
2. Reuse current pure queue selection; group advancement is terminal ownership
   and is explicitly excluded.
3. Move eligibility, capacity, blocked-project, and source arbitration behind
   the boundary without durable effects.
4. Remove the duplicate inline selection path.
5. Lower `runWorkLoop` complexity/span and forbid queue pointer escape.

## Acceptance

- Candidate selection is pure for a captured fleet/ledger snapshot.
- Queued candidates carry enough identity for later revalidation.
- No activation, deferral mutation, reservation, claim, persist, Run
  registration, terminal/group advancement, or process effect occurs here.
- The exact pre-approved architecture target is met.

## Verification

Table/property tests, mutation tests, race/repeat composition tests, architecture
gate, delta lint, UBS, and `make check-fast`.

## Escalate when

Stop if one source cannot be represented without changing its normative claim
or reservation authority.
