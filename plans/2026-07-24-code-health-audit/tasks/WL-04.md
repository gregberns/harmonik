# WL-04 — Extract run-spawn and completion ownership

## Dispatch metadata

- Group / priority: run architecture / P0
- Execution profile: `sol_xhigh`
- Reviewer profile: `sol_xhigh`
- Depends on: `WL-03`, `CQ-03`, `BR-04`, `WL-REC-01`
- Work type: serial concurrency/lifecycle decomposition

## Objective

As the final outer-loop extraction, move capacity accounting, goroutine
ownership, and typed per-run completion handoff from `runWorkLoop` into one
spawn owner consuming the settled claim/Run and terminal contracts. Every
acquisition and join must release exactly once on success, error, cancellation,
panic recovery, and shutdown.

## Exclusive lease

The spawn/goroutine/completion region of `workloop.go`, the target owner chosen
by `ARCH-01`, Run registry/capacity adapters, and focused tests. Sole
`dispatch_spine` writer.

## Required work

1. Define an immutable spawn request from the claimed Run and a typed completion
   result from the thin `beadRunOne` coordinator.
2. Centralize acquisition and reverse-order cleanup.
3. Make goroutine lifetime and shutdown joining explicit.
4. Add a deterministic executor-start latch and a typed completion cause that
   distinguishes shutdown cancellation from normal failure.
5. Close `shutdown_inflight` with a production-composition trace proving
   executor start → shutdown begin → cancelled terminal → queue cancel → joined
   return, with no queue-failure effect.
6. Add mutations that map shutdown cancellation to failure or return before
   the join; prove that the shutdown oracle rejects them.
7. Hand the typed completion to the already-extracted terminal owner; do not
   invent another completion callback contract.
8. Delete the old inline ownership and meet the exact approved function
   metrics.

## Acceptance

- Every acquisition has one mechanically reviewable release path.
- Failed start cannot leak registration, capacity, claim, or queue ownership.
- Shutdown waits or hands off according to the reviewed lifecycle contract.
- An in-flight shutdown has a deterministic production-composition oracle that
  distinguishes cancellation from failure and proves the run is joined before
  return.
- Shutdown cancellation never records a false queue failure.
- `runWorkLoop` becomes a small loop over gate → select → reserve/claim → spawn.

## Verification

Fault injection at every acquisition, a named `shutdown_inflight`
production-composition trace, cancellation-as-failure and return-before-join
mutations, race/stress/leak/repeat tests, controlled panic test, architecture
gate, delta lint, UBS, and `make check-fast`.

## Escalate when

Stop if cleanup ownership conflicts with process/session scope or the durable
terminal contract; resolve that contract before implementation.
