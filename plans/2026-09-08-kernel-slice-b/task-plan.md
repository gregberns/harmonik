## Part 1 — The load-bearing design calls this plan makes

1. **POINT_TO_POINT lives in `kernel/transport`, not in `harmonikd` and not in a new segment.** Competing-consumer delivery is channel semantics — the substrate's job. The shape: per (channel, group), the transport holds one **group queue** plus **per-member lease queues**; assignment is **round-robin over live members** (deterministic, which is what makes G1's exact 5+5 assertable); a member acks a delivery on `Deliver` success, nacks it on failure, and a member detach nacks everything it held. Ack/nack/detach are the only new verbs `harmonikd`'s dispatcher learns. The lease state is kernel-held, like Slice A's subscription queues — it survives the plugin process, which is precisely what makes G2 and G3 satisfiable.
2. **Two-kernel testing without two boxes = N `transport.Transport` instances linked by an in-process double.** New subpackage `kernel/transport/memmesh`: it forwards channel declarations, fans PUBSUB out across nodes, registers remote group members, and merges LOOKUP reads — all as direct function calls inside one OS process, no sockets between kernels. This is the p1 §5 "two in-mem kernels wired by an in-process transport double", generalized to N. **It is explicitly NOT the Slice C cross-machine transport decision (Q-1 stays open)** and not the 6-method transport seam; the seam `memmesh` implements is the minimal private set of cross-kernel operations Slice B needs, with a comment saying exactly that, so no future agent mistakes the double for the transport verdict.
3. **The group queue's authority is the declaring kernel.** The kernel whose plugin declared the channel (the dispatch primary's) holds the group queue and does the round-robin; remote members reach it through the double. This is C3's "primary holds the queue; primary dies → restart it, you do not rebuild the network", expressed at the transport level.
4. **The 5+5 gate runs THREE in-process kernels, not two.** C3 locks one `dispatch` instance per daemon and the `primary` role holds the queue rather than consuming work (p1 §3: "every *other* instance runs the worker side"). Two kernels therefore yield one worker and 10→10+0. Two same-namespace plugins on one kernel would break the namespace-is-THE-identity model. So: the double is N-node; N=2 is the default harness (G2, G3, G4); the G1 load-balance case instantiates N=3 (primary + two workers) — which is also the topology the original measured claim used (laptop publishes, dgx+mini each take 5). This is the one operator-visible call — see E1.
5. **The `dispatch` plugin's state lives in kernel journals, and only journals.** KV stays deferred to the comms slice (Slice A's deferral list; not reopened). Primary: an `accepted` journal (jobs in, each stamped with a dispatch-owned `job_id`), a `forwarded` marker journal; rehydration on `Start` is journal replay. Workers: a `done` journal that doubles as the dedupe set — effectively-once = at-least-once + dedupe-on-`job_id` (the VC-7 pattern). Envelope `message_id` cannot serve as job identity because a requeue republish gets a fresh stamp; job identity is the plugin's, which is exactly the boundary the kernel contract draws.
6. **Crash-loop budget/backoff stays deferred, deliberately, even though `dispatch` is the first non-toy plugin** (Slice A named that as the trigger). The C5 gate needs requeue-to-survivors, not relaunch: a dead worker's work moves; nothing has to restart it. Re-arm the trigger: host restart policy lands when a deployment has a plugin with no surviving peer.

### B1 — POINT_TO_POINT in the transport  **Segment:** `kernel/transport`. **Deps:** none (dispatchable immediately).
Group state per (channel, group): one group queue, per-member lease queues, round-robin assignment over live members, and the lease verbs — `Ack` (delivery done, forget it), `Nack` (delivery failed, requeue to the group queue for reassignment), member detach (nack everything queued + leased to that member). `Subscribe` grows the `group` argument for PTP channels; a PTP subscribe with no group, or a pubsub subscribe with one, is a typed refusal. `Publish` with `group_key` set returns a typed "not implemented in this slice" error (deferred — see decisions). All state kernel-held and process-independent, same as Slice A's `Subscription`.
**Acceptance:** 10 enqueued envelopes across 2 members land 5+5 in assignment order; `Nack` reassigns to the other member exactly once (no copy retained by the failed member); detach with 3 leased + 2 queued reassigns all 5; a single member drains the whole queue (degenerate 1:1 case per the contract comment); PUBSUB behavior byte-identical to Slice A (its tests untouched and green); vocabulary check green.

### B2 — The in-process mesh double  **Segment:** `kernel/transport/memmesh`. **Deps:** B1.
Link N `transport.Transport` instances in one process behind a minimal seam: declaration forwarding (first (name,type) wins mesh-wide; conflicting type rejected), PUBSUB fan-out to every node's matching subscriptions, remote group membership against the declaring kernel's group queue (call 3 above), and a hook the LOOKUP merge (B4) and REQUEST_REPLY correlation (B3) plug into. Carries the "this is NOT the Q-1 cross-machine transport" comment verbatim. No goroutine-per-hop cleverness — direct calls under the same locks discipline the transport already has.
**Acceptance:** publish on node A, subscriber on node B receives with `origin_node` = A and `origin_seq` monotonic per (A, channel); 10 PTP envelopes published on A with members on B and C land 5+5; a conflicting type declaration from another node is rejected; kill nothing — this package is pure in-process plumbing, its faults are exercised at B10.

### B3 — REQUEST_REPLY, in-memory  **Segment:** `kernel/transport` + wiring in `kernel/cmd/harmonikd` (`kernelserver.go`). **Deps:** none for the single-kernel core; B2 for the cross-node leg.
Kernel-correlated one-question-one-answer: `Request` (with `timeout_ms`, and an immediate `INTEREST_NONE` return when nobody serves — never a silent timeout), `Serve` (server-stream of envelopes + `request_id`), `Respond` (by `request_id`; non-empty `error` fails the requester's call). Wire the three RPCs into `kernelServer` (they are 3 of the 19; the embed's `Unimplemented` stops covering them). Cross-node: a request on one kernel reaches a server on another through the memmesh hook.
**Acceptance:** round-trip with a correlated reply, payload opaque both ways; timeout fires when the server never responds; `INTEREST_NONE` returns immediately with no server attached; `Respond` with a stale/unknown `request_id` is a typed refusal; cross-node round-trip through memmesh.

### B4 — LOOKUP, in-memory  **Segment:** `kernel/transport` (or a sibling `kernel/lookup` if it will not share transport's locks — implementer's call) + wiring in `kernelserver.go`. **Deps:** local core none; B2 for the merge.
Local map per channel: `LookupPut` (writer = this node, revision monotonic per writer), `LookupGet`/`LookupList` returning EVERY claimant — with two nodes claiming one key through the memmesh merge, both entries come back and the kernel picks neither. **Scope fence:** the memmesh merge is a direct in-process read of peer maps; the *replicated* LOOKUP protocol (gossip, read-repair, `boot_id`, the disk-wipe experiment) stays Slice C, untouched.
**Acceptance:** revision strictly monotonic per writer across puts; a two-node name clash returns two entries; TTL expiry honored on the local clock; `LookupGet` on an empty key returns zero entries, not an error.

### B5 — Roster as pure local functions  **Segment:** new `kernel/roster` + `RosterList` wiring in `kernelserver.go`. **Deps:** none.
The liveness state machine as pure functions of this box's own consecutive probe results, exactly per the contract enums: 3 consecutive failures → SUSPECT, 6 → DEAD, never-probed → UNKNOWN; announced intents (`SLEEPING`/`DRAINING`) map to their `Reason` values. No probe loop, no network, no clock read inside the functions (counts and instants come in as arguments — the injected-clock discipline `internal/runloop` set the precedent for). Wire `RosterList` to return self + the statically configured peer set with liveness computed by these functions from whatever observations the composition root feeds it (in this slice: trivially ALIVE for linked memmesh peers, UNKNOWN otherwise).
**Acceptance:** table tests covering every transition including flap sequences (fail×2 → ok resets the counter); an announced sleep yields DEAD/ANNOUNCED_SLEEP without consuming probe failures; `RosterList` on a 2-node harness shows both boxes and `self`; zero imports beyond `contract` + std.

### B6 — The `dispatch` plugin  **Segment:** new module `tools/dispatch/` (library core + go-plugin adapter + `cmd/dispatch/main.go`), added to `go.work` and `SEGMENT_MODULES`. **Deps:** none (imports `contract` + std + go-plugin only — tool-isolation enforces it; unit tests construct the `Server` directly, the way `tools/echo/echo_test.go` does).
One namespace `dispatch`, role from launch args (`--role=primary|worker`), manifest per role. Primary declares `dispatch.work` (POINT_TO_POINT), `dispatch.status` (PUBSUB), and `dispatch.submit` (PUBSUB, public) with an interest in `submit`; on each submitted payload: stamp a `job_id`, `JournalAppend(accepted, sync=true)`, publish on `dispatch.work`, journal the forwarded marker. Worker declares an interest in `dispatch.work` with `group="workers"`; on `Deliver`: dedupe against its `done` journal by `job_id` (a duplicate is acked and dropped, loudly logged), do the "work" (journal the record), publish completion on `dispatch.status`. On `Start`, either role rehydrates by journal replay (accepted minus forwarded = re-forward; the done set = the dedupe state) — the plugin process holds nothing a `kill -9` can lose. Target the same order of size as echo (~150–250 lines of core); if it needs any kernel RPC outside the contract, STOP — the API is wrong.
**Acceptance:** unit-level with a fake `KernelServiceClient`: a submit produces exactly one accepted record, one work publish, one forwarded marker; a re-`Start` after a simulated crash re-forwards only the unforwarded; a worker delivered the same `job_id` twice journals it once; role args parse and each role's manifest matches this paragraph.

### B7 — Mesh composition: `harmonikd mesh`  **Segment:** `kernel/cmd/harmonikd` + a small `Args` field on `kernel/host.LaunchSpec`. **Deps:** B2, B5, B6.
A `mesh` subcommand: one OS process, N kernels (each its own `transport.Transport`, own SQLite state file, own loopback KernelService listener, own admin listener), linked by memmesh, each launching its one configured plugin (path + sha256 + args) — config from a file, nodes and plugins never baked into source. `host.LaunchSpec` gains `Args`, passed to the child's `exec.Cmd`, so `--role` reaches the dispatch binary; the spec (args included) persists across reload as it does today. Per-node admin `/plugin/reload` unchanged in shape. The single-node `serve` path stays byte-compatible — mesh is an additional verb, not a rewrite.
**Acceptance:** a 2-node mesh config boots to both plugins RUNNING with distinct PIDs and distinct kernel/admin addresses; `RosterList` on either node shows both; a publish to `dispatch.submit` on node A's kernel is observable in the primary's `accepted` journal; reload against node B's admin restarts only node B's plugin (node A's PID unchanged); existing `daemon_test.go`/`drain_test.go` untouched and green.

### B8 — The PTP delivery loop + requeue (the C5 path)  **Segment:** `kernel/cmd/harmonikd` (`dispatch.go`). **Deps:** B1, B6, B7.
Teach the dispatcher/pluginManager pair the lease verbs: a PTP dispatcher takes its member's next leased envelope, `Deliver`s, then `Ack`s on success and `Nack`s on failure — replacing the PUBSUB-only "held" mechanic for PTP (held = leased; the lease is transport-held, so nothing rides on the dispatcher's memory). A `Deliver` that fails `Unavailable` (worker died) nacks → the transport reassigns to a surviving member. Extend the drain gate: reloading a plugin with PTP interests drains in-flight `Deliver`s exactly as today, then detaches its member (nacking its lease queue) before `Kill()` and re-attaches after relaunch — the invariant comment gains the third leg: *leased-but-undelivered work is nacked back to the group queue; there is still no state in which an envelope is both unfinished and unowned.*
**Acceptance (bead-level; the slice verdict is B10):** with two harnesstestplugin workers in one group, a `kill -9` of one mid-`Deliver` (the slow-handler env knob exists for this) ends with every envelope journaled exactly once across the two; a reload of a PTP-subscribed plugin mid-stream loses nothing and duplicates nothing at unit scale; deliberate-stop still logs `Canceled` vs `Unavailable` distinctly.

### B9 — Four-type conformance harness (VC-13, full)  **Segment:** `kernel/cmd/harmonikd` (chaos-tagged test + `harnesstestplugin` extension), neutral names only. **Deps:** B3, B4, B7, B8.
A `//go:build chaos` test against a live `harmonikd mesh` process, using the harnesstestplugin (extended by env knobs to declare/serve each channel type under its neutral `harnesstestplugin.*` names): PUBSUB copy-to-all across nodes; POINT_TO_POINT exactly-one across nodes; REQUEST_REPLY correlated reply (and the `INTEREST_NONE` fast-fail); LOOKUP all-claimants-returned on a two-node clash. This resolves the `08` §Slice 1 scope note for good: VC-13 is now at full width.
**Acceptance:** the four cases pass against the live mesh process under `make chaos`; each asserts the artifact (journal rows, returned entries), never just an exit code; the vocabulary probe (VC-14, with B0's widened noun list) runs alongside.

### B10 — The Slice B chaos gate *(assessor-owned)*  **Deps:** B7, B8, B9.
Standing harness in `tools/dispatch/chaos_test.go` (`//go:build chaos`; `make chaos` picks it up via `SEGMENT_MODULES` — B6 already added the module), copying the echo gate's shape: launch a real `harmonikd mesh` built from the slice tip, drive it over gRPC + admin HTTP, assert the artifact. Cases: **G1** — N=3 mesh (per E1), 10 paced jobs into `dispatch.submit`, assert the two workers' `done` journals hold 5 and 5 with set-equality against the sent `job_id`s; **G2** — also N=3 (a requeue needs a surviving peer, and N=2 has only one worker): `kill -9` one of the two workers mid-job (slow-work knob), assert every job done exactly once with the dead worker's in-flight job among the survivor's completions; **G3** — VC-12 re-run: jobs flowing at ≥100 msg/s, reload the *primary* (byte-distinct binary) mid-stream and separately reload a worker mid-stream; assert zero loss, zero duplicates by `job_id` set-equality, every kernel PID unchanged, reload inside the echo gate's recalibrated budget; **G4** — run B9's conformance cases. Echo's own chaos gate runs unchanged in the same `make chaos` sweep (the reload regression the Slice B definition names). Dated `assessments/YYYY-MM-DD-HHMM-kernel-slice-b/` created from `_TEMPLATE` before the run, written as it happens, pinned to the slice commit; failures become cases in `test/exploratory/cases/`.
**Acceptance:** the whole gate holds against the live mesh process, three consecutive runs, re-runnable by one command (`make chaos`). Slice C does not start until this holds. Any lost or duplicated job is a hard stop put to the operator.

### Resolved in this plan (architect-level; operator may veto, none waits)
- PTP semantics (group queue, round-robin, lease/ack/nack/detach-requeue) live in `kernel/transport`; `harmonikd` learns only the verbs. Assignment is deterministic round-robin — fairness/work-stealing refinements wait for the backpressure work (VC-11, comms slice).
- The double is `kernel/transport/memmesh`, a minimal private seam, explicitly not the Q-1 cross-machine transport decision and not the 6-method seam.
- Group-queue authority = the declaring kernel (C3 at the transport level).
- `dispatch` state on journals only; KV stays deferred to the comms slice. Job identity (`job_id`) and dedupe are the plugin's, not the kernel's.
- `group_key` ships as a typed not-implemented error; trigger: the first consumer needing per-key ordering.
- Multi-plugin-per-kernel registry (per-connection namespace identity) stays deferred; trigger: the comms migration or any deployment putting two plugins on one node.
- Crash-loop budget stays deferred despite `dispatch` being the first non-toy plugin — C5 is requeue-to-survivors, not relaunch; re-armed trigger: a plugin with no surviving peer.
- Role config travels as `LaunchSpec.Args`; it persists across reload with the spec, which is what keeps a reloaded worker a worker.
- LOOKUP conformance uses the memmesh direct merge; the replicated protocol (`boot_id`, read-repair, disk-wipe experiment) is Slice C, unmoved.

## Part 5 — Residual risks
- **The memmesh double drifting into a shadow transport.** It is one process-hop away from "just make it talk TCP". The not-Q-1 comment plus keeping the seam unexported are the guards; a reviewer seeing the seam grow past what B2 names should flag it.
- **G3's zero-duplicate assertion rests on the plugin's journal-replay rehydration.** A cursor bug shows up as a duplicate at the gate — which is the gate doing its job — but keep the `job_id` dedupe logging loud so a near-miss (deduped duplicate) is visible in the assessment record, not silently absorbed.
- **Primary reload while workers hold leases** must not requeue-storm: the leases are transport-held on the primary's *kernel*, untouched by the plugin process dying — assert lease counts across the G3 reload in the assessment evidence, not just the final set.
- **`kernelserver.go` is a five-task touchpoint** (B3, B4, B5 wiring + B7/B8 nearby). Cheap to manage — additions are append-only methods — but sequence the merges rather than racing them.
- **Deterministic 5+5 depends on both workers being attached before the first job.** The gate must gate job submission on both members' registration (observable via the transport's member count or a first status heartbeat), or G1 flakes on boot order.
